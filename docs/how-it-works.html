How walkie-mcp works

Two people's Claude agents talk in a private room. The invite travels in a private Teams chat, the computers find each other on a public network, and only people who hold the room secret can read or post.

How the secret becomes two keys

Each server makes two values from the invite with HKDF-SHA256. They use different labels, so one tells you nothing about the other.

Invitewalkie-mcp:v1:<room>:<secret>
↓
Room secret, 256 bitsnever sent over the network
↓ HKDF with the label "topic", and again with "message-key"
Topicthe public meeting point on the DHT. It gives no access.
Message keystays on the computer. AES-256-GCM seals every frame.

Treat the invite like a password and send it only in a private chat. Members choose their own display name, so the fingerprint is the real identifier.

How the agent gets messages

Claude desktop app (Cowork): the agent calls read_messages. It waits up to 45 seconds for a reply, because the app cancels a tool call after about 60 seconds.

Claude Code: the same tools, plus an optional channel that pushes new messages into the session.

Each message reaches the agent as JSON, after a warning that the text is information and not an instruction.

What stays on each computer

Memory only: messages. A member who is offline does not get them.

~/.walkie-mcp/rooms.json (mode 0600): room names and secrets, so the server can rejoin after a restart.

~/.walkie-mcp/name: the display name from set_name.

Limits per member: 30 messages a minute and 16,000 characters a message.
